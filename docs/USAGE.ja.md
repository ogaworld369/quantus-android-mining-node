# 使い方ガイド

**言語：** [English](USAGE.md) · 日本語 · [简体中文](USAGE.zh-Hans.md) · [Español](USAGE.es.md) · [हिन्दी](USAGE.hi.md) · [العربية](USAGE.ar.md) · [한국어](USAGE.ko.md) · [Русский](USAGE.ru.md) · [Français](USAGE.fr.md)

このアプリは、Quantus Network（QTC メインネット）の**フルノード**を Android スマホで動かすものです。チェーンを同期し、すべてのブロックを自分で検証し、ピアへデータを中継します。既定ではブロック生成をしない通常ノードとして動き、任意でマイニングもできます（既定はオフ。下の**マイニング**の節を見てください）。**ウォレットはありません**し、シードフレーズを扱うこともありません。このアプリが保持しうる秘密は、ご自身で貼り付けるマイニング報酬の Inner Hash だけです。

> 現在の状態: v4.2.5 を公開済み（2026-11-18、最新版）。マイニング性能の改善版です。同梱マイナーが、4つの nonce をまとめて転置レイアウトで処理するバッチエンジンで PoW ハッシュを計算するようになり、Pixel 9a の実測でスレッドあたり約1.22倍になりました。同梱ノードバイナリは変更ありません（v4.2.4 は 2026-11-17 の、v4.2.3 の外部監査へのセキュリティ修正版）。署名付き APK は [GitHub Releases](https://github.com/ogaworld369/quantus-android-mining-node/releases) で SHA-256 チェックサム付きで配布しています。それ以前のテスト版は開発者から直接お渡ししていました。

## 動作要件

- Android 12 以降・arm64 の端末
- 空き容量: ノードのデータベースはプルーニング済み（保持は最新256ブロック分のみ）で、小さく収まります。実測（Pixel 9a、同期完了時点、2026-11-05）では合計 1.30GB（アプリ 96MB＋ノードデータ 1.20GB）でした。目安として 3GB 程度の空きを確保してください
- インターネット接続。初回同期は Wi-Fi を強く推奨します（下記）

動作確認済み: **Pixel 9a（GrapheneOS）**。その他の端末は動作見込みですが未確認です。別の機種で試した方は、動いた・動かなかったを含め GitHub の Issue で報告いただけると助かります。確認済みリストはその報告で増やしていきます。

## インストール

1. APK ファイルを [GitHub Releases](https://github.com/ogaworld369/quantus-android-mining-node/releases) から用意します（インストール前に、リリースに併記された SHA-256 チェックサムでファイルが正しいか確認してください）。
2. ファイルアプリで APK を開き、Android に聞かれたらそのアプリからのインストールを許可します。
3. インストールして、**Quantus Node** を開きます。

## 初回起動と初回同期

1. （任意）先に**表示名**と**テレメトリ**設定を済ませておくと楽です（「設定」参照）。設定の反映にはノードの再起動（停止 → 開始）が必要です。
2. **「ノードを開始」**を押します。
3. 状態が**「同期中」**になり、ベストブロックが最高ブロックへ向けて増えていきます。Pixel 9a では初回同期（ジェネシスから）は毎秒約50ブロックのペースで、**2時間前後**が目安です。同期が完了すると約12秒に1ブロックの通常運転になり、状態表示が同期完了に変わります。
4. 初回同期中は、できれば**充電しながら Wi-Fi** で。モバイル回線でも同期できますが、通信量が多く、電池の減りも目立ちます（モバイル回線での同期中、30分で約11%の消費を実測）。同期完了後の定常負荷は小さいです。

アプリを開いたままにする必要はありません。ノードはフォアグラウンドサービスとして、画面を消しても、他のアプリを使っていても動き続けます（稼働中は通知が1つ常駐表示されます）。停止して再開しても、ダウンロード済みのチェーンは端末に残り、同期は続きから再開します。

## 画面の見方

画面の下部に3つのタブ（ホーム／つながり／会員カード）があります。ノード詳細と設定へはホームから移動します。

- **ホーム** — ベストブロック、ノードの状態（停止／起動中／同期中／同期完了／失敗）、主ボタンが中心です。稼働中は接続ピア数と今回の稼働時間、現在の QTC 価格も出ます。起動に失敗した場合は通常の停止ではなく「失敗」として再試行ボタンが出ます。変更した設定がまだ反映されていない場合は、その確認へのリンクが出ます
- **つながり** — 自分のノードのネットワークの様子を描く画面です。接続しているピアと、自分が記録したチェックポイントの残像が広がります。競うための数字ではなく、つながりの様子を見るための画面で、ランキングはありません
- **ノード詳細** — ベストブロック／最高ブロック（自分のノードの位置と、ネットワークの先端）、同期差、ピア数、稼働時間と、**診断**のセクション（終了コード、サービスのメモ、起動試行ごとの記録、**ログを共有**）があります。停止中は前回セッションの値ではなく、累計の航跡を表示します
- **会員カード** — 会員番号（デバイスID）と、端末内の記録から3つの数字（参加開始日、チェックポイント数、連続記録の最長日数）を載せた会員カードです。記録はこの端末にだけ保存され、外部に送信されることはなく、金銭価値もありません。自分の貢献の足跡で、見せるかどうかは自分で決められます
- **設定** — 下記の設定を、ページ型のハブに並べたもの。アプリの版数は **このアプリについて** のページに表示され、同梱のノードとマイナーの **オープンソースライセンス** もそこにあります

## 設定

- **テレメトリに表示する**（既定オフ）— オンにすると、ノード名と稼働状態が公式テレメトリ（telemetry.quantus.com）で誰でも見える状態になります。一覧に載せたい場合だけオンにしてください。反映は次回のノード開始時（停止 → 開始）です
- **表示名** — テレメトリに出るノードの名前。ダイアログで編集します。ノードがこの名前を使うのは **テレメトリに表示する** がオンのときだけです（そのときは接続中のピアにも見えます）。オフのときは既定名 `quantus-android-node` で動きます。空欄なら既定名です。反映は次回のノード開始時です
- **言語** — 端末の設定に従うか、9言語（日本語・英語・簡体中文・スペイン語・ヒンディー語・アラビア語・韓国語・ロシア語・フランス語）から選べます。選ぶと即反映されます
- **稼働を記録する（DePIN）**（既定オフ）— オンにすると、ノードの稼働と中継の記録に署名して、この端末に残します（10分ごとのチェックポイント）。記録が自動でどこかへ送られることはありません。設定から証明バンドルとしてファイルに書き出し、自分で共有できます。オフにすると記録は止まりますが、それまでの記録は端末に残ります
- **設定をロック** — 上の設定（テレメトリ・表示名・言語・稼働の記録）とマイニングの設定（マイニングのオン・オフと Inner Hash）をロックして、ノードを動かしたまま置いてある端末でうっかり変更してしまわないようにします。誤操作防止のためのもので、PIN はありません。ノードの開始・停止はロックされません。設定を変えるときは **設定をロック** をオフにしてください。
- **マイニング**（既定はオフ） — 同梱された公式マイナーで、この端末自体がマイニングもできます。先に報酬の Inner Hash が必要です。下の **マイニング（任意）** を見てください。

設定は自動でノードを再起動しません。稼働中にテレメトリを変えた場合や、テレメトリがオンのときに表示名を変えた場合は、変えた項目に未適用の印がつき、ホームにも未適用設定の確認リンクが出ます。反映は次回のノード開始時（停止 → 開始）です。

**ログを共有** は **ノード詳細 → 診断** の中にあります。ノードのログをテキストで共有するもので、不具合報告のときにこれを添付してください。公開の場に貼る前に内容を確認してください。ログには自ノードのグローバル IP アドレスやピア情報が含まれうる場合があります。共有ダイアログでは、表示名・アプリ内パス・ログ中の IP アドレス（この端末自身のネットワークアドレス、ピア経由で知った外向きのアドレス、ピアのアドレス）のマスキングが使えます（既定オン）。ループバックのアドレスはそのまま残ります。

## ストレージ

**設定 → ストレージ** には、アプリが使っている容量が6つの数字で表示されます。**チェーンDB**、**ノード全体**の残り、**ログ**、**DePINの記録**、**合計（アプリのデータ）**、**この端末の空き容量**です。ノードの稼働中は数字が変わり続けるので、目安として見てください。

このページの操作は1つだけで、**チェーンDBを消して再同期** です。削除されるのはチェーンDB（この端末がこれまでに同期したブロックデータ）だけです。ノードのネットワーク鍵、マイニングの設定と保存した Inner Hash、DePIN の ID とその記録、航跡、ログ、アプリの設定はすべて残ります。この操作はノードが停止しているときだけ使え、取り消しはできません。次にノードを開始すると、同期は最初からやり直しになり、時間と通信量がかかります（Pixel 9a で約2時間）。

## 価格

ホームには現在の QTC 価格が表示されます。アプリは **CoinGecko**（api.coingecko.com）から約1時間に1回取得します。取得は**既定でオン**で、スイッチは価格シート（ホームの価格をタップ）と **設定 → 外部からの情報** にあります。取得で送られるのは価格の問い合わせと、アプリ名とバージョンを示す User-Agent（`QuantusNode/<version>`）だけで、ノードの情報・会員番号・記録が送られることはありません。ただし CoinGecko からは、この端末の IP アドレスが見えます（接続先のサーバならどれも同じです）。スイッチをオフにすると取得は止まり、価格の行には「オフ」と表示され、シートにはダッシュが表示されます。以前に取得した値があっても残りません。

## マイニング（任意）

このアプリは、同梱された公式マイナーを使って、このスマホ自体でマイニングもできます。マイニングは**既定ではオフ**で、オフのままでもノードはまったく同じように動きます。オンにするとノードがバリデータとして起動し、報酬は（アプリではなく）ご自身に支払われます。

**マイニングをオンにするには、先に報酬の Inner Hash が必要です。** 報酬は通常のアドレスには支払われません。プロトコルの決まりで、Inner Hash という秘密から導出される**ワームホールアドレス**に支払われます。

Inner Hash の受け取り方：

- PC で公式ノードのコマンド `quantus-node key quantus --scheme wormhole` を実行します。**Address**（報酬の宛先）、**Inner Hash**（このアプリに必要な値）、**Secret phrase**（バックアップ）の3つが表示されます。Secret phrase は安全な場所に、オフラインで保管してください。
- 公式ウォレットを使っている場合は、同じコマンドに `--words` を付けて、求められたときにシードフレーズを入力すれば、同じ3つの値を導出できます。入力するのは PC の上だけです。このアプリに入れることは決してありません。同じシードフレーズのウォレットには、報酬が自動で現れます。
- あるいは、公式 Quantus ウォレットアプリで **Encrypted Account** のメニューを開き、**Inner Hash** を選ぶ方法もあります。そのアカウントの Inner Hash がそのまま表示され、報酬はその Encrypted Account に支払われます。PC は不要で、シードフレーズがウォレットアプリの外に出ることもありません。

次に、アプリ側で：

1. **設定 → マイニング** を開き、**Inner Hash** の値を貼り付けます（`0x` の後に16進数64桁が続く形です）。入れるのは Inner Hash だけです。シードフレーズや秘密鍵は絶対に入れないでください。Inner Hash はこの端末が作るすべてのブロックに書き込まれ、公開されます。
2. 入れた Inner Hash に対してノードが報告する報酬アドレスが、アプリに表示されます。信用する前に、入手元と同じアドレス——ツールの **Address**、またはウォレットアプリの **Encrypted Account**——と一致するか照合してください。
3. マイニングをオンにして、ノードを再起動します（停止 → 開始）。マイニングの設定は、次にノードを起動したときから反映されます。

**保存する前に、Inner Hash をよく確認してください。** 間違っていると、報酬はその誤った宛先に支払われ、取り戻すことはできません。保存した値はこの端末の中だけにあり、画面・ログ・共有テキストに表示されることはありません。

**ワーカー数と熱。** CPU ワーカーは 1 / 2 / 4 / 自動 から選べます（既定は 2。ノード自身のために、常に1コアが空けてあります）。ワーカーが多いほど発熱と電池の消費が増えます。スマホが熱くなると、プラットフォームの熱レベル「中程度」でマイニングは自動で弱まり、「深刻」以上ではそのセッションの間は停止します。スマホを限界まで回すことはありません。

**期待値について正直に書いておきます。** スマホのハッシュレートでは、ブロックが見つかるまでの期待待ち時間は非常に長く、どんなテスト期間よりも長くなります。ここでのマイニングは、稼ぐ手段ではなく、参加する手段です。

## 新しい端末への引っ越し

DePIN の ID とその記録は、新しいスマホへ引っ越しできます。両方の端末で **設定 → 端末間の移行** を開いてください。簡単な方法はファイル1つで済みます。

1. **旧端末**で **かんたん移行ファイルを作成** を押します。アプリがファイルを作成し、**移行コード** を1回だけ表示するので、控えておいてください。この時点で、旧端末の記録は止まります。
2. ファイルを **新端末** へ渡します（方法は問いません）。新端末で **移行パッケージを取り込む** を押し、ファイルを選んで移行コードを入力します。
3. 新端末がパッケージを検証し、引き継ぐ ID の内容（デバイスID、チェックポイント数、最初と最後の記録の日付）を表示します。値を確認して、**かんたん移行で確定する** を押してください。ID はこの端末のものになり、ここで記録を始められます。
4. 新端末に8桁の **確認番号** が表示されます。旧端末で **確認番号を入力して： この端末の鍵を消す** を押し、その番号を入力してください。鍵は番号が一致したときだけ消えます。その後、残っている引っ越しファイルも削除してください。

手順4が終わるまでは、ID のコピーが2つ存在します。**引っ越しファイルは鍵と同じものとして扱ってください**。中には ID のシードが移行コードで暗号化されて入っており、ファイルとコードの両方を持つ人は、ID とその履歴のすべてを引き継げてしまいます。できるだけ別々に渡し、どちらも公開の場に出さないでください。ファイルが新端末に届かなかった場合は、旧端末で **かんたん移行を取り消す** と記録を再開できます。ただし、新端末が取り込み済みの場合は絶対に取り消さないでください。

移行の前に知っておくことが2つあります。両方の端末に v4.2.4 以降が必要です（古い版では新しいパッケージを読めません）。また、移行パッケージの上限は 16 MiB（チェックポイント約19,900件分）です。履歴がこれを超えると、書き出しの時点でその旨が表示され、受け取れないファイルは作られません。

同じページの **その他の操作** には、より厳格な手順の移行もあります。確認番号1つの代わりに、準備通知・確認許可・受領・完了応答のファイルを、2台の端末のあいだで1つずつ交換していく方式です。

## 日常の使い方

- ノードが止まるのは、**「ノードを停止」**を押したとき、アプリを強制終了したとき、スマホを再起動したときだけです
- スマホを再起動した後は、アプリを開いて**「ノードを開始」**を押し直してください（起動時の自動開始は未実装です）
- メーカー独自の省電力（Samsung、Xiaomi など）が強い端末では、バックグラウンドのサービスが止められることがあります。ノードが勝手に止まる場合は、システム設定でこのアプリを電池最適化の対象外にしてください
- 余ったスマホを24時間コンセントに挿して使う場合は、時々バッテリーの状態を見てください。古いリチウム電池は膨張することがあります。風通しの良い場所に置き、端末に充電上限の設定があれば使うのがおすすめです

## 困ったとき

- **ノードがすぐ終了する** — **ノード詳細 → 診断 → ログを共有** でログを取り、GitHub の Issue（不具合テンプレート）に添付してください。ログには起動の試行ごとに終了理由が残っています
- **ピア数が0のまま** — 接続を確認して、停止 → 開始を1回試してください
- **同期が止まる（ネットワークは進むのに自分のベストブロックが動かない）** — この形を検出すると、アプリが自動でノードを再起動します（24時間に最大3回まで）。繰り返す場合は安定した Wi-Fi に切り替え、停止 → 開始を1回試してください
- **テレメトリに自分のノードが出ない** — テレメトリ設定がオンか、オンにした後にノードを再起動したかを確認してください（掲載は確認済みです。開発者自身のノードが公式一覧に表示されています）
- **容量について** — データベースは設計上、最新256ブロック分にプルーニングされます。アプリをアンインストールすると、データベースとノードの身元キーに加えて、保存した Inner Hash と、DePIN の ID とその記録のすべても削除されます。再インストールすると新しい身元で同期し直しになるので、記録を残したい場合は、先に新しい端末へ引っ越してください（上の **新しい端末への引っ越し** を参照）

質問・端末の動作報告・提案は GitHub の Issue へどうぞ。セキュリティの問題は公開 Issue ではなく [SECURITY.md](../SECURITY.md) の手順でお願いします。
