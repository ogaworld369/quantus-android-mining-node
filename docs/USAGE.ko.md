# 사용 가이드

**언어:** [English](USAGE.md) · [日本語](USAGE.ja.md) · [简体中文](USAGE.zh-Hans.md) · [Español](USAGE.es.md) · [हिन्दी](USAGE.hi.md) · [العربية](USAGE.ar.md) · 한국어 · [Русский](USAGE.ru.md) · [Français](USAGE.fr.md)

이 앱은 Android 스마트폰에서 Quantus Network(QTC 메인넷)의 **풀 노드**를 실행합니다. 체인을 동기화하고, 모든 블록을 스스로 검증하며, 피어에게 데이터를 중계합니다. 기본값으로는 비검증자로 동작하고, 채굴도 할 수 있지만 기본값이 꺼짐인 선택 기능입니다(아래 **채굴** 절 참조). **지갑은 없고** 시드 구절을 다루는 일은 전혀 없습니다. 이 앱이 보관할 수 있는 유일한 비밀은 직접 붙여 넣는 채굴 보상 Inner Hash뿐입니다.

> 상태: v4.2.4 공개됨(2026-11-17), 현재 버전. v4.2.3 외부 감사의 보안 수정 버전입니다. 앱은 이제 노드의 RPC 주소와 ID를 노드 자체의 시작 출력에서 가져와 폴링할 때마다 대조합니다. 표시 이름은 텔레메트리가 켜져 있을 때만 노드에 전달되고, mDNS와 메트릭 엔드포인트는 꺼졌으며, 이전 확인 번호는 이전 자체의 비밀값으로 키가 지정됩니다(v4.2.3도 2026-11-17에 공개되었으며 동봉 바이너리를 다시 빌드한 유지보수 버전이었습니다). 서명된 APK는 SHA-256 체크섬과 함께 [GitHub Releases](https://github.com/ogaworld369/quantus-android-mining-node/releases)에 게시되어 있습니다. 이전 테스트 빌드는 유지관리자가 직접 공유했습니다.

## 동작 요구 사항

- Android 12 이상, arm64 기기
- 여유 공간: 노드 데이터베이스는 프루닝되어(최신 256개 블록만 유지) 작게 유지됩니다. 실측(Pixel 9a, 전체 동기화 완료 시점, 2026-11-05): 총 1.30GB(앱 96MB + 노드 데이터 1.20GB). 여유 공간은 최소 약 3GB 정도 확보해 두세요
- 인터넷 연결. 첫 동기화에는 Wi-Fi를 강력히 권장합니다(아래 참조)

지금까지 확인된 기기: **GrapheneOS를 실행하는 Pixel 9a**. 다른 기기도 동작할 것으로 예상되지만 확인되지는 않았습니다. 다른 기종에서 시도해 보셨다면, 동작 여부와 함께 GitHub Issue로 알려 주세요. 확인된 기기 목록은 그 보고로 늘어납니다.

## 설치

1. APK 파일을 [GitHub Releases](https://github.com/ogaworld369/quantus-android-mining-node/releases)에서 준비합니다(설치 전에 릴리스와 함께 게시된 SHA-256 체크섬을 확인하세요).
2. 파일 앱으로 APK를 열고, Android가 물으면 해당 출처에서의 설치를 허용합니다.
3. 설치한 뒤 **Quantus Node**를 엽니다.

## 첫 실행과 초기 동기화

1. (선택) 먼저 **표시 이름**과 **텔레메트리** 옵션을 설정해 두면 편합니다(설정 참조). 설정 변경은 노드 재시작(정지 → 시작) 후 적용됩니다.
2. **노드 시작**을 누릅니다.
3. 상태가 **동기화 중**으로 표시되고 베스트 블록이 최고 블록을 향해 올라갑니다. Pixel 9a에서는 제네시스부터의 첫 동기화가 초당 약 50블록 속도로 진행되어 **약 2시간**이 걸립니다. 동기화가 끝나면 약 12초마다 새 블록이 도착하고 상태가 동기화 완료로 바뀝니다.
4. 첫 동기화 중에는 가능하면 **충전하면서 Wi-Fi**에 연결해 두세요. 모바일 데이터로도 동기화는 되지만, 데이터 다운로드량이 많고 배터리 소모도 눈에 띄게 큽니다(모바일 데이터 동기화 중 30분에 약 11% 소모를 실측). 동기화 완료 후의 상시 부하는 작습니다.

앱을 열어 둘 필요는 없습니다. 노드는 포그라운드 서비스로 실행되어, 화면을 꺼도 다른 앱을 사용해도 계속 동작하며, 실행 중에는 상시 알림이 표시됩니다. 정지 후 다시 시작해도 다운로드한 체인은 기기에 남아 있어 동기화는 이어서 재개됩니다.

## 화면 설명

화면 아래에 홈, 연결, 회원 카드의 세 가지 탭이 있습니다. 노드 상세와 설정은 홈에서 이동합니다.

- **홈** — 베스트 블록, 노드 상태(정지 / 시작 중 / 동기화 중 / 동기화 완료 / 실패), 그리고 주 버튼 하나가 중심입니다. 노드가 실행 중일 때는 연결된 피어 수와 이번 세션의 가동 시간, 현재 QTC 가격도 표시됩니다. 시작에 실패하면 일반 정지가 아니라 다시 시도 버튼과 함께 실패로 표시됩니다. 변경한 설정이 아직 반영되지 않았으면 그 확인으로 가는 링크가 표시됩니다
- **연결** — 내 노드의 네트워크 모습을 그리는 화면입니다. 연결된 피어와 내가 기록한 체크포인트의 잔상이 펼쳐집니다. 경쟁을 위한 숫자가 아니라 연결의 모습을 보기 위한 화면이며, 순위는 없습니다
- **노드 상세** — 베스트 블록 / 최고 블록(내 노드의 위치와 알려진 네트워크 선단의 비교), 동기화 간격, 피어 수, 가동 시간, 그리고 **진단** 섹션(종료 코드, 서비스 메모, 시작 시도별 기록, **로그 공유**)이 있습니다. 노드가 정지 중일 때는 이전 세션의 값이 아니라 누적 항적을 표시합니다
- **회원 카드** — 회원 번호(기기 ID)와 이 기기 기록의 숫자 3개(참여 시작일, 체크포인트 수, 최장 연속 일수)를 담은 회원 카드입니다. 기록은 이 기기에만 저장되고 외부로 전송되지 않으며 금전적 가치도 없습니다. 자신의 기여의 발자취이며, 보여줄지는 본인이 정합니다
- **설정** — 아래 설정을 페이지 허브 형태로 모은 것입니다. 앱 버전은 **이 앱 정보** 페이지에 표시되며, 내장된 노드와 채굴기 바이너리의 **오픈소스 라이선스**도 거기에 있습니다

## 설정

- **텔레메트리에 표시** (기본 꺼짐) — 켜면 노드 이름과 실시간 상태가 공식 텔레메트리(telemetry.quantus.com)에 누구나 볼 수 있게 공개됩니다. 목록에 올리고 싶을 때만 켜세요. 다음 노드 시작(정지 → 시작)부터 적용됩니다.
- **표시 이름** — 텔레메트리에 표시되는 노드 이름. 대화 상자에서 편집합니다. 노드는 **텔레메트리에 표시**가 켜져 있을 때만 이 이름을 사용합니다(이때는 연결된 피어에게도 보입니다). 텔레메트리가 꺼져 있으면 노드는 기본 이름 `quantus-android-node`로 실행됩니다. 비워 두면 기본 이름이 됩니다. 다음 노드 시작부터 적용됩니다.
- **언어** — 기기 설정을 따르거나, 9개 언어(일본어, 영어, 간체 중국어, 스페인어, 힌디어, 아랍어, 한국어, 러시아어, 프랑스어) 중 선택할 수 있습니다. 선택하면 즉시 적용됩니다.
- **내 활동 기록(DePIN)** (기본 꺼짐) — 켜면 노드의 가동과 중계 작업에 대한 서명된 기록을 이 기기에 남깁니다(10분마다 체크포인트). 기록이 저절로 어딘가로 전송되는 일은 없습니다. 설정에서 증명 번들 파일로 내보내 직접 공유할 수 있습니다. 끄면 기록은 멈추지만, 기존 기록은 기기에 남습니다
- **설정 잠금** — 위의 설정(텔레메트리, 표시 이름, 언어, 활동 기록)과 채굴 설정(채굴 켜기/끄기와 Inner Hash)을 잠가, 노드를 실행한 채로 둔 휴대전화에서 실수로 변경되지 않게 합니다. 오조작 방지를 위한 기능일 뿐 PIN은 없으며, 노드의 시작과 정지는 잠기지 않습니다. 설정을 다시 변경하려면 **설정 잠금**을 끄세요.
- **채굴**(기본값 꺼짐) — 노드는 내장된 공식 채굴기로 이 기기에서 채굴도 할 수 있습니다. 먼저 보상 Inner Hash가 필요합니다. 아래 **채굴(선택 사항)**을 보세요.

설정은 스스로 노드를 재시작하지 않습니다. 노드가 실행 중일 때 텔레메트리를 변경하거나 텔레메트리가 켜진 상태에서 표시 이름을 변경하면, 변경한 항목에 아직 적용되지 않았다는 표시가 붙고, 홈에도 적용 대기 중인 설정을 확인할 수 있는 링크가 표시됩니다. 반영은 다음 노드 시작(정지 → 시작) 때 이루어집니다.

**로그 공유**는 **노드 상세 → 진단** 안에 있습니다. 노드 로그를 텍스트로 공유하는 기능으로, 문제를 보고할 때 이것을 첨부해 주세요. 공개된 장소에 로그를 붙여 넣기 전에 내용을 먼저 확인해 주세요. 로그에는 내 노드의 공인 IP 주소와 피어 정보가 포함될 수 있습니다. 공유 대화 상자에서는 표시 이름, 앱 내부 경로, 로그 속 IP 주소(이 기기 자체의 인터페이스 주소, 피어를 통해 알게 된 외부 주소, 피어의 주소)를 가릴 수 있습니다(기본 켜짐). 루프백 주소는 그대로 읽을 수 있습니다.

## 저장 공간

**설정 → 저장 공간**에는 앱이 사용하는 용량이 여섯 가지 숫자로 표시됩니다. **체인 DB**, 나머지 **노드 전체** 데이터, **로그**, **DePIN 기록**, **합계(앱 데이터)**, **이 기기의 남은 용량**입니다. 노드가 실행 중일 때는 숫자가 계속 변하므로 추정치로 보세요.

이 페이지의 유일한 작업인 **체인 DB를 지우고 다시 동기화**는 체인 DB(이 기기가 지금까지 동기화한 블록 데이터)만 지웁니다. 노드의 네트워크 키, 채굴 설정과 저장된 Inner Hash, DePIN ID와 그 기록, 항적 기록, 로그, 앱 설정은 모두 남습니다. 이 작업은 노드가 정지 중일 때만 쓸 수 있고 되돌릴 수 없습니다. 다음에 노드를 시작하면 동기화가 처음부터 다시 시작되어 시간과 데이터가 듭니다(Pixel 9a에서 약 2시간).

## 가격

홈에는 현재 QTC 가격이 표시됩니다. 앱은 **CoinGecko**(api.coingecko.com)에서 약 1시간에 한 번 가져옵니다. 가져오기는 **기본값이 켜짐**이며, 스위치는 가격 시트(홈에서 가격을 탭)와 **설정 → 외부 정보**에 있습니다. 가져올 때 보내는 것은 가격 조회와, 앱 이름과 버전을 밝히는 User-Agent(`QuantusNode/<version>`)뿐입니다. 노드 정보, 회원 번호, 기록은 절대 전송되지 않습니다. 다만 CoinGecko에서는 이 기기의 IP 주소를 볼 수 있는데, 이는 연결하는 모든 서버가 마찬가지입니다. 스위치를 끄면 아무것도 가져오지 않습니다. 가격 행에는 “끔”이라고 표시되고 시트에는 대시가 표시됩니다. 이전에 가져온 값이 있어도 남지 않습니다.

## 채굴(선택 사항)

이 앱은 내장된 공식 채굴기로 이 스마트폰에서 직접 채굴도 할 수 있습니다. 채굴은 **기본값이 꺼짐**이며, 꺼져 있어도 노드는 완전히 똑같이 동작합니다. 켜면 노드가 검증자로 시작되고, 보상은 앱이 아니라 본인에게 지급됩니다.

**채굴을 켜려면 먼저 보상용 Inner Hash가 필요합니다.** 보상은 일반 주소로 지급되지 않습니다. 프로토콜상 Inner Hash라는 비밀에서 도출되는 **웜홀(wormhole) 주소**로 지급됩니다.

Inner Hash를 받는 방법:

- PC에서 공식 노드의 명령 `quantus-node key quantus --scheme wormhole`를 실행합니다. **Address**(보상이 갈 주소), **Inner Hash**(이 앱에 필요한 값), **Secret phrase**(백업)의 세 가지가 표시됩니다. Secret phrase는 안전한 곳에 오프라인으로 보관하세요.
- 공식 지갑을 이미 쓰고 있다면, 그 시드 구절에서 같은 값을 도출할 수도 있습니다. 같은 명령에 `--words`를 붙이고, 물어볼 때 구절을 입력하세요 — 입력하는 곳은 PC이며, 이 앱에는 절대 입력하지 않습니다. 같은 시드 구절의 지갑에는 보상이 자동으로 나타납니다.

그다음 앱에서:

1. **설정 → 채굴**을 열고 **Inner Hash** 값을 붙여 넣습니다(`0x` 뒤에 16진수 64자리가 오는 형태입니다). 입력하는 것은 Inner Hash뿐입니다. 시드 구절이나 비밀 키는 절대 입력하지 마세요. Inner Hash는 이 기기가 만드는 모든 블록에 기록되어 공개됩니다.
2. 입력한 Inner Hash에 대해 노드가 보고하는 보상 주소가 앱에 표시됩니다. 신뢰하기 전에 도구의 **Address**와 일치하는지 대조하세요.
3. 채굴을 켜고 노드를 다시 시작합니다(정지 → 시작). 채굴 설정은 다음 노드 시작부터 반영됩니다.

**저장하기 전에 Inner Hash를 꼼꼼히 확인하세요.** 잘못 입력하면 보상은 그 잘못된 주소로 지급되며 되돌릴 수 없습니다. 저장된 값은 이 기기 안에만 있고, 앱은 이를 화면·로그·공유 텍스트에 절대 표시하지 않습니다.

**워커와 발열.** CPU 워커는 1 / 2 / 4 / 자동 중에서 고를 수 있습니다(기본값 2. 노드 자체를 위해 항상 코어 하나를 비워 둡니다). 워커가 많을수록 발열과 배터리 소모가 커집니다. 스마트폰이 뜨거워지면 플랫폼의 열 단계 "보통"에서 채굴이 자동으로 약해지고, "심각" 이상에서는 그 세션 동안 멈춥니다. 스마트폰을 한계까지 돌리는 일은 없습니다.

**기대치는 솔직하게:** 스마트폰의 해시레이트로는 블록을 찾을 때까지의 기대 대기 시간이 매우 길어, 어떤 테스트 기간보다도 깁니다. 여기서의 채굴은 버는 수단이 아니라 참여하는 수단입니다.

## 새 기기로 이전

DePIN ID와 그 기록은 새 스마트폰으로 이전할 수 있습니다. 두 기기 모두에서 **설정 → 기기 간 이전**을 여세요. 간편한 방법은 파일 하나로 끝납니다.

1. **이전 기기**에서 **간편 이전 파일 만들기**를 누릅니다. 앱이 파일을 만들고 **이전 코드**를 한 번만 보여주니 적어 두세요. 이 순간 이전 기기의 기록이 멈춥니다.
2. 파일을 **새 기기**로 전달합니다(방법은 자유). 새 기기에서 **이전 패키지 가져오기**를 누르고 파일을 골라 이전 코드를 입력합니다.
3. 새 기기가 패키지를 검증하고 인계받을 ID의 내용(기기 ID, 체크포인트 수, 첫 기록과 마지막 기록 날짜)을 보여줍니다. 값을 확인한 뒤 **간편 이전으로 확정**을 누르세요. ID는 이제 이 기기의 것이 되며, 여기서 기록을 시작할 수 있습니다.
4. 새 기기에 8자리 **확인 번호**가 표시됩니다. 이전 기기에서 **확인 번호 입력: 이 기기의 키 삭제**를 누르고 그 번호를 입력하세요. 키는 번호가 일치할 때만 지워집니다. 그 뒤 남은 이전 파일도 지워 주세요.

4단계가 끝나기 전까지는 ID의 복사본이 두 개 존재합니다. **이전 파일을 키처럼 취급하세요.** 안에는 ID의 시드가 이전 코드로 암호화되어 들어 있어서, 파일과 코드를 모두 가진 사람은 ID와 그 전체 기록을 인계받을 수 있습니다. 가능한 한 따로따로 전달하고, 둘 다 공개된 장소에 올리지 마세요. 파일이 새 기기에 닿지 않았다면, 이전 기기에서 **간편 이전 취소**를 하면 그쪽에서 기록을 다시 시작할 수 있습니다. 단, 새 기기가 이미 가져온 뒤에는 절대 취소하지 마세요.

이전 전에 알아둘 점이 두 가지 있습니다. 두 기기 모두 v4.2.4 이상이 필요합니다(이전 버전은 새 패키지를 읽을 수 없습니다). 그리고 이전 패키지의 상한은 16 MiB로, 체크포인트 약 19,900개 분량입니다. 기록이 이를 넘으면, 새 기기가 거부할 파일을 만드는 대신 내보내기 단계에서 그 사실을 알려줍니다.

같은 페이지의 **기타 작업**에는 더 엄격한 단계별 이전도 있습니다. 확인 번호 하나 대신, 준비 알림, 확인 허가, 영수증, 완료 응답 파일을 두 기기가 하나씩 주고받는 방식입니다.

## 일상적인 운용

- 노드가 멈추는 경우는 **노드 정지**를 눌렀을 때, 앱을 강제 종료했을 때, 스마트폰을 재부팅했을 때뿐입니다.
- 스마트폰 재부팅 후에는 앱을 열고 **노드 시작**을 다시 눌러 주세요(부팅 시 자동 시작은 아직 미구현입니다).
- 일부 제조사의 Android(Samsung, Xiaomi 등)는 배터리 절전이 강해서 백그라운드 서비스를 멈출 수 있습니다. 노드가 저절로 멈춘다면, 시스템 설정에서 이 앱을 배터리 최적화 대상에서 제외해 주세요.
- 여분의 스마트폰을 24시간 충전기에 꽂아 두고 쓰시나요? 가끔 배터리 상태를 확인하세요. 오래된 리튬 배터리는 부풀 수 있습니다. 통풍이 잘 되는 곳에 두고, 기기가 충전 상한 설정을 제공하면 사용하는 것을 권장합니다.

## 문제가 생겼을 때

- **노드가 바로 종료됨** — **노드 상세 → 진단 → 로그 공유**로 로그를 가져와 GitHub Issue(버그 리포트 템플릿)에 첨부해 주세요. 로그에는 시작 시도마다 종료 이유가 남아 있습니다.
- **피어 수가 0에서 안 늘어남** — 연결을 확인한 뒤 정지 → 시작을 한 번 해 보세요.
- **동기화가 멈춤(네트워크는 앞서가는데 내 베스트 블록이 움직이지 않음)** — 앱이 이 형태를 감지하면 노드를 자동으로 재시작합니다(24시간에 최대 3회). 반복되면 안정적인 Wi-Fi로 바꾼 뒤 정지 → 시작을 한 번 해 보세요
- **텔레메트리에 내 노드가 안 보임** — 텔레메트리 옵션이 켜져 있는지, 켠 뒤에 노드를 재시작했는지 확인하세요(목록 표시는 확인됐습니다. 유지관리자 본인의 노드가 공식 목록에 표시되고 있습니다).
- **용량 관련** — 데이터베이스는 설계상 최신 256개 블록으로 프루닝됩니다. 앱을 삭제하면 데이터베이스와 노드의 신원 키뿐 아니라 저장된 Inner Hash와 DePIN ID 및 그 기록 전체도 지워집니다. 재설치하면 새 신원으로 다시 동기화하므로, 기록을 남기고 싶다면 먼저 새 기기로 이전하세요(위의 **새 기기로 이전** 참조).

질문, 기기 동작 보고, 제안은 GitHub Issue로 환영합니다. 보안 문제는 공개 Issue가 아니라 [SECURITY.md](../SECURITY.md)의 절차를 따라 주세요.
